# 记忆系统

## 文档描述

debug-fixer 的记忆不是日志仓库，而是一个会不断压缩经验的系统。目标不是“记住更多”，而是让后续 BUG 更快命中规律、识别误判、缩短定位路径。

本文档定义一个短期工作台和三层长期记忆：

0. **短期 session 记录**：本轮 debug 的假设、证据、埋点、用户反馈和下一步。
1. **事件记忆**：单个已确认 BUG 的症状、首次偏离点、修复和教训。
2. **模式记忆**：跨多个 BUG 归纳出的稳定规律。
3. **反模式记忆**：反复被证伪的错误假设、常见误区、危险捷径。

记忆只帮助生成假设，不替代当前证据。

---

## 默认目录结构

如果项目没有既定约定，使用下面的结构：

```text
.debug/
  session/
    {session_id}.md
  memory/
    index.md
    episodes/
    patterns/
    anti-patterns/
```

`session/` 是短期工作台，确认回合通过后删除或归档。`memory/` 是长期经验库，只写已经确认且可复用的内容。

---

## 记忆层级

### 0. 短期 session 记录

当进入埋点、首次修复失败、或方向自疑时，立即创建或更新 `.debug/session/{session_id}.md`。它记录本轮 debug 的事实和状态，避免多轮交互后丢失上下文。

用途：
- 保存当前假设、已排除假设和证据等级
- 记录本轮改动、埋点位置、session ID 和待清理项
- 保存用户反馈与日志结论
- 给确认后的长期记忆提供原材料

### 1. 事件记忆

一条修复对应一条事件记忆。它记录具体发生了什么、怎么修、为什么修对。

用途：
- 给下一次相似 BUG 提供初始假设
- 保留可复用的调试线索
- 作为模式记忆的原材料

### 2. 模式记忆

当多个事件记忆共享同一类根因家族、同一类链路断点、或同一类症状传播方式时，提炼成模式记忆。

用途：
- 识别“这一类 bug 一般先看哪里”
- 让系统从具体案例上升到规律
- 给调用链追溯提供优先级

### 3. 反模式记忆

当某个假设在多个 session 里反复被证伪，或者某个排查方向经常浪费时间，就写成反模式记忆。

用途：
- 防止 AI 重复走错路
- 给方向自疑提供稳定的负向约束
- 让系统知道“什么经常看起来像，其实不是”

## 读取顺序

快速诊断时按下面顺序读取：

1. `.debug/session/{session_id}.md`（如果这是同一轮未结束的 debug）
2. `.debug/memory/index.md`（如果存在）
3. 模式记忆
4. 反模式记忆
5. 事件记忆

读取原则：
- 先看模块/症状/架构关键词，再看具体文件名
- 命中后优先读高置信、最近验证过的记忆
- 记忆只作为假设输入，不计入根因证据
- 当前运行时证据永远优先于历史记忆

---

## 写入规则

### 短期 session 记录

进入埋点、首次修复失败、方向自疑时必须写入或更新。它是本轮默认产物，不需要用户额外要求。

确认修复前，不要把 session 里的暂定结论写入长期记忆。确认修复后，先从 session 中提取可复用信息，再删除或归档 session。

### 事件记忆

每次确认回合通过后，先写事件记忆。它是最小粒度的知识单元；如果用户还没完成确认回合，就不要把暂定结论写进长期记忆。

### 模式记忆

当满足任一条件时，更新或新建模式记忆：
- 同一根因家族在两个及以上事件记忆中重复出现
- 同一症状传播方式在多个文件/模块中重复出现
- 同一类调用链断点反复出现

### 反模式记忆

当满足任一条件时，更新或新建反模式记忆：
- 同一假设在多个 session 中被证伪
- 同一排查方向反复无效
- 某个“看起来很像”的症状在历史上经常误导判断

---

## 合并与降权

记忆要会“长”，也要会“压缩”。

- session 记录只服务本轮，不长期堆积
- 相似事件记忆要合并到同一模式下
- 低价值、低置信、重复信息要降权
- 旧记忆如果长期没有再次验证，优先级要下降
- 新记忆如果和旧规律冲突，以当前更强证据为准

---

## 脱敏

以下内容不写入长期记忆：
- `password` / `secret` / `token` / `apiKey` / `credential` 的原值
- 完整页面文本
- 用户个人信息
- 完整源码或完整日志

只保留：
- 关键字段摘要
- 触发条件
- 首次偏离点
- 修复方式
- 可复用教训
