## 为什么需要 Debug Fixer？

大部分 AI 调试是无效的。模型看到 BUG → 猜一个修复 → 你说没用 → 再猜一个 → 五个回合后，代码比一开始更烂，而且没人知道到底试了什么。

Debug Fixer 用一条简单规则打断这个循环：**一次静态猜测，之后全部用运行时证据说话。** 第一个修复不成立，就停止猜测。注入埋点，收集真实数据，在真正的源头修。

```
猜 → 失败 → 再猜 → 又失败 → 继续猜   ← 普通 AI 调试
猜 → 失败 → 埋点 → 证据 → 源头修复    ← Debug Fixer 强制执行的流程
```

灵感来自 Cursor 的 Debug Mode，实现为 Claude Code Skill，自带 Agent、埋点模板和清理工具链。

## 核心特性

### 1. "只猜一次"规则

静态代码分析最多只能确定一个根因。如果那个不对，说明你缺的不是灵感，是信息。Debug Fixer 强制阻断后续猜测，把你推进埋点管道。为什么重要：连续猜测是最常见的调试失败模式，每一次错误的修改都在让代码变得更难理解。

### 2. 多维扫描，而非线性追溯

一个看起来是"CSS 渲染不对"的 BUG，根因可能是一个状态管理的竞态条件。传统调试沿着一条调用链追。扫描 Agent 四条线同时走，找它们的交叉点——因为大多数真实 BUG 就住在这个交叉点上。

### 3. 真正的埋点工具，不是 console.log

`console.log` 是调试界的便利贴。不能聚合、不能清理、不能跨会话共享。Debug Fixer 提供 7 种语言的标准埋点模板，统一 JSON 格式输出，`#region DEBUG` 包裹，修复后一条命令清理干净。注入 → 复现 → 读日志 → 找到偏差 → 一键移除。零残留。

### 4. 卡住了就请师傅看

盯着同一个 BUG 久了会产生隧道视野——你反复看那三个文件、翻来覆去试同一个假设的不同变体。师傅审查 Agent 用干净上下文启动。它读你试过的所有方案，从零重新扫描代码，然后像一个高级工程师审查初级工程师的代码一样说话——告诉你哪里没看到、为什么当前方案走不通。可以多次触发，只分析不修改。

### 5. CSS 深度感知

客户端 BUG 的根因大量集中在 CSS，而不是 JS——flexbox 居中偏移、auto 尺寸计算、viewBox 自适应、transform-origin。多维扫描 Agent 和埋点策略都专门针对浏览器布局行为做了强化。核心启发式——"逻辑没问题但 BUG 还在 → 检查 CSS"——直接内建在流程里。

## 安装

```bash
# 项目级安装（推荐）
cp -r debug-fixer .claude/skills/

# 用户级安装（所有项目生效）
cp -r debug-fixer ~/.claude/skills/
```

`launch-debugger.js` 和 `cleanup-debug-blocks.js` 需要 Node.js。无其他依赖。

## 快速开始

```
/debug-fixer 流程图查看时不能放大到 300%，100% 之后尺寸没变化
```

Skill 会自动生成 Session ID、派扫描 Agent、判定快速通道或引导埋点。你只需要在被要求时复现 BUG。

## 适用场景

- 崩溃、测试失败、构建错误
- UI 错位、样式问题、布局异常
- 数据不对、行为不符预期、边界条件失败
- 竞态条件、异步时序问题、缓存问题
- 前端、后端、全栈项目均可

## 设计原则

- **用证据说话** —— 一次静态修复后，所有修改必须有运行时证据支撑
- **改源头不修症状** —— 找到数据/样式首次偏离的位置，只改那里
- **工具化而非建议化** —— 提供可执行的标准模板和清理脚本，不是模糊的指导
- **解释为什么而非命令做什么** —— 每条规则附理由，不堆砌命令词
